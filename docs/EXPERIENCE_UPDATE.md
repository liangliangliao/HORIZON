# 初次上手、三维与反馈改进

基线：`codex/unity-prototype-v0-3@864d607`。开发分支：`codex/playable-feedback-3d`。

| 玩家反馈 | 本轮可试玩变化 | 验证方式 |
| --- | --- | --- |
| 不知道拖到哪里、什么算成功 | 金色接收圈在角色上方；拖动时实时显示目的日期；进入圈后变亮、加粗、播放接收音并显示“松手”；目标文字位于携带卡牌前面；成功飞向固定日期 | 原椭圆边界测试；完整真实拖拽；手势所有权与一次提交测试；竖屏截图 |
| 缺乏三维氛围、事物没有象征性 | 自制曲面衣服和圆润道具网格、陶盆与弯曲叶片、台灯、木长椅、实体地平线、分层浮岛；三个主光方向、实际阴影与接触阴影、天空、Bloom、光轨 | 网格数据与外法线、Shader 导入测试；Unity 真实渲染；手机帧率验收 |
| 强化奖励不明显 | 正面回声光波、三维飞散、星形星尘飞向钱包、实际余额计数；成长投放保持安静，回声兑现强化 | 钱包一次领取规则；恢复后不重放领取演出；真人反馈辨识 |
| 结果一闪而过、看不懂发生了什么 | 顶部“来源 → 到达日”，独立资源变化卡片，长期后果说明；多回声逐条确认，读档回到当前阅读位置；负面回声给下一步选择留空间 | 连续阅读与中断恢复 Play Mode 测试；现有完整局流程 |

日期由卡牌决定，拖得更高不改变规则。这样新玩家只需判断接收圈是否亮起，无需先理解自由排程。圈外释放不消耗资源；手势未开始、输入被遮罩阻挡或第二根手指释放都不能意外提交。

奖励沿用原来的持久收据和额度。星尘买外观；预测成功继续扩大信息可见性。余额动画和资源变化显示都使用真实已结算结果，不用虚构的大数值替代反馈。

结果不自动跳到下一天。进入结果后短暂防止上一个松手误触继续，之后由玩家决定阅读时间。恢复结果只呈现已保存状态；不会再次领取或重复播放星尘收集。

本轮增加 5 项检查，合计 73 项。CI 继续录制既有 22 张 1080×1920 真实 Unity 画面、十秒 GIF，并在验证通过后构建双架构 Android APK。检查状态以本轮提交的工作流为准。

## 仍需要真实设备和玩家验收

1. 未读说明的新玩家能否在 30 秒内完成第一张牌，且能指出回声到达日。
2. 单手拖拽是否能连续完成三次，圈外释放是否清楚知道卡牌未使用。
3. 第一次回声后能否说出源行动和实际变化，多条回声是否能全部读完。
4. 中断后恢复是否仍知道自己正在读哪一条；精力不足时是否自然选择恢复。
5. 中低端手机的帧率、发热、粒子与 Bloom 成本；有无遮挡、中文缺字和过强闪光。
6. 第一局到重开的实际用时、第三次未来站的情感效果及自愿重玩意愿。

当前仍是自制三维原型资产，未获得新玩家数据。第七天完整剧情、成熟角色动画、30 天完整战役和分享目标应用兼容性也不能被这次代码改动视为全部完成。
