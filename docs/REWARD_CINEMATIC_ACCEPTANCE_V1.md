# 奖励与动画 v1.0 需求核对

核对来源：用户提供的 Reward System Specification v1.0 与 Cinematic & Animation Specification v1.0。分母固定为奖励 22 组、动画 28 组；部分完成不计分，两份方案必须各自达到 85%。原 Master v0.4.2 的 89.6855% 不用于本次核算。

## 实现与证据

本轮代码审查：奖励 22/22（100%），动画 27/28（96.43%）。状态为“实现待验收”，只有当前提交对应的命名测试实际全部执行通过，才计入自动化支持率。APK、Android 原生显示、美术体验和真机帧率另行验收，不能用代码比例替代。

原交付 `54f0030` 已通过业务 262/262、Unity 332/332、APK 和 Android 模拟器验证。本轮新增真实景深、五张预演关键帧、分层投影世界、Shader Graph、16 类特效、LOD/Flipbook、运行时降级与帧率记录，必须重新通过完整流程；旧 APK 不能代替新增功能的验证。功能和设备复验方法见 [余项实现说明](CINEMATIC_REMAINING_IMPLEMENTATION.md)。

Unity 6 的 RenderGraph 兼容配置仍在编辑器构建阶段完成；GLES3 保留已验证的渲染路径。景深和径向折射使用独立 Renderer Feature，不依赖先前引起红屏的 URP 内置 HDR 后处理。新的 Android 检查实际绘制景深、验证蓝色通道，并核对预演生成五张可解码帧。

当前提交的结果由 `HORIZON-Cinematic-Specification-Acceptance`、`HORIZON-Cinematic-Reward-Previews` 和 Android 原生产物提供。特效专项测试使用明确标注的渲染测试样例；实际业务可达性与奖励文案仍由真实领域事件的截图回归覆盖。

## 核验方法

详细的原要求、源文件、入口与命名测试保存在 [JSON 清单](REWARD_CINEMATIC_ACCEPTANCE_V1.json)。执行 `python3 tools/report_cinematic_acceptance.py --results artifacts --enforce`，报告包括提交、清单校验和、每组执行测试及两份方案独立比例。缺少测试结果不会被当成通过。

剩余验收条件：实际 Android 手机普通场景 60 FPS、重大演出最低 30 FPS 数据，以及美术、声音和触觉体验的人工确认。统计单元测试或模拟器渲染成功不能替代真机性能；A28 因此保持“部分实现”。
