# HORIZON Emotional Cinematic System V4.0

## 情绪化电影演出系统 · 完整开发规范

- 版本：V4.0
- 日期：2026-11-27
- 状态：设计规范，待代码实施和真机验收
- 适用项目：HORIZON / 远见（Unity 竖屏游戏）
- 前置规范：`ENERGY_CINEMATIC_SYSTEM_V2.md`、`ENERGY_CINEMATIC_V3_VISUAL_REBUILD.md`
- 约束：沿用现行玩法、真实结算、因果记录、存档与奖励规则。本规范不增加抽奖、随机加倍、付费续玩或强制观看，不以成瘾、失去自主控制或推定的多巴胺释放为验收目标。

## 1. 核心问题与设计目标

V2.0 解决能量的运动规律，V3.0 解决美术、动作、空间和表现协同，V4.0 解决整个演出为什么值得观看。三个规范应共同实施，而非互相取代。

**最高原则：技术特效服务于情绪表达；情绪表达服务于真实成果的价值。**

目标体验是：理解发生了什么 → 对有意义的变化产生期待 → 看见进展 → 感受到有力量的释放 → 看清真实成果 → 获得满足与自主结束的权利。

用户用前戏与高潮作类比，指出铺垫质量决定高潮体验。转换成游戏设计语言，是戏剧性预备、张力发展、转折、释放和收束。这里不把刺激强度当作价值，也不以延长玩家停留、反复追逐奖励或操控生理反应为目标。

## 3. 情绪体验导演：六段结构

| 段落 | 体验目标 | 必须可见的事件进展 | 不合格表现 |
| --- | --- | --- | --- |
| 建立意义 | 理解此次真实事件 | 过去行动、成果主题、明确主体 | 无关远景、长篇说明、没有焦点 |
| 预备 | 对即将发生的变化形成合理期待 | 主体进入动作预备，能量有明确来路 | 物体静止，仅背景发光 |
| 发展 | 看见真实变化持续发生 | 动作、路径、连接、光色、空间共同演化 | 延长等待、重复同一种光圈 |
| 转折 | 理解变化即将完成 | 动作收紧、真实接触或结构完成 | 假近失、虚构风险、故意隐藏已知收益 |
| 释放 | 感受到成果出现的力量 | 主体动作、局部光核、火团、传播、真实成果同一事件 | 独立爆炸与结果脱节，遮住主体 |
| 收束 | 读清结果并产生完成感 | 真实数值、最终实体、来源、可查看收据 | 无意义二次爆炸、长时间静态远景、自动诱导下一局 |

情绪曲线是导演用于表达故事的定性模型，不是实时监控玩家的情绪或生理状态。每个阶段必须对应可理解的画面事件，不允许仅靠倒计时或推迟揭晓来制造等待。

## 4. 技术架构与职责边界

采用既有 `RewardPlan`、`RewardDirector`、`CinematicEnergy`、`CinematicOutcome`、`CinematicDirector` 及 V3.0 渲染基础。先审查当前源代码，不另起一套业务结算或互相竞争的时钟。下列名称是建议职责，并不代表仓库已有这些类。

| 模块 | 职责 |
| --- | --- |
| EventReceipt | 只读真实事件ID、行动来源、资源精确增减、因果节点、实际日期、结果类型 |
| EmotionalStoryboard | 按真实事件语义选择段落、主题、分镜和呈现目标 |
| VisualProfile | 主体造型、动作、色谱、空间、光效与声音的主题配置 |
| MotionTrack | 预备动作、位姿、发力、接触、反作用、稳定；按主体实际尺度调校 |
| EnergyTrack | 复用V2的蓄积、波动、白光、火团、传播和余辉；不脱离动作锚点 |
| EnvironmentTrack | 真实空间光照、反射、背景变化、前中后景、阴影 |
| CameraTrack | 由叙事主体决定镜头，控制构图与移动；适配竖屏和减弱动效 |
| OutcomeTrack | 真实成果出现、精确数值、实体状态变化、成本与收益的区别 |
| AudioHapticTrack | 原创音色、接触、释放、余韵；与动作cue一致，可关闭 |
| ReceiptPresenter | 全部真实结果可回看，随时跳过电影而不损失结果 |

所有表现轨道使用统一导演时钟。事件ID用于确定性视觉采样，不用于奖励随机化。暂停冻结表现，跳过直接呈现完整收据，重播不再次结算，后台恢复保持一致状态。结果应可立即查看，演出不是获取奖励的必要条件。

## 5. 标准分镜：真实 TIME ECHO 样片

场景示例：过去一次学习行动已带来今天的能力增长。只在真实事件记录支持时采用以下表现；不能根据示例虚构结果。

| 时间（建议） | 画面 / 动作 | 能量及音画 | 真实成果呈现 |
| --- | --- | --- | --- |
| 0–0.5秒 | 过去行动的印记与当前角色入画，主体清晰 | 微光，环境声保持克制 | 标出实际来源日，结果可查看 |
| 0.5–1.4秒 | 印记沿真实时间路径抵达，角色作出回应 | 局部流光、深度轨迹；音效体现移动 | 明确正在兑现的是哪一次行动 |
| 1.4–2.6秒 | 核心接近接触点、局部动作与结构变化 | 复用V2/V3分层光效与实际灯光，颜色随主题演化 | 不虚构未知奖励、额外节点或未来变化 |
| 2.6–2.9秒 | 短暂预备、接触动作完成 | 可选择短暂收声或局部收束，不强制等待 | 真实来源仍可辨识 |
| 2.9–3.5秒 | 接触/开启/连接，主体表现反作用 | 局部柔边白核、非规则火团、外向传播、同步声音 | 真实成果在接触后迅速出现 |
| 3.15–4.3秒 | 实体形成并稳定，真实数值进入焦点 | 扩散逐渐衰减，动态光照随之恢复 | 精确数值单调增长至实际终值，成本另标明 |
| 4.3–5.5秒 | 呈现完成后的实体状态，收束回归 | 自然余辉、轻柔尾音 | 完整收据、来源、继续或结束由用户决定 |

上述时间约5.5秒，不含用户自主阅读收据时间。主释放与真实成果首次可见的建议偏移不超过0.35秒（继承V3样片指标）；需要结合实际动作与可读性调试。普通事件明显压缩；较复杂的真实因果事件按真实节点增加时间，而非固定拉长所有演出。

## 6. 主体、能量与画面的实现要求

### 6.1 主体先于特效

- 主体是行动与成果的具象载体：学习使用书本、透镜、知识结构；关系使用实际角色或连接结构；能力使用工具和能力实体；财富使用实际储备和容器。
- 动作要表现明确因果：走近→接触，握持→发力，箱盖→开启，连接端点→闭合。可用 AnimationClip 或现有导演的确定性姿态轨道。
- 预备、释放、反作用、稳定应连贯，不能用全屏震动替代主体动作。
- 美术需满足V3的原创或合法授权资产、PBR材质、倒角、法线、AO、接触阴影与空间构图要求。不能把程序化几何模型加光后宣称商用品质。

### 6.2 能量和场景的协同

- 使用与主体实际发力点绑定的世界锚点，而非统一置于镜头后方。
- V2的独立白光、非规则能量团与扩散余波在V3的多层渲染中工作；素材品质、粒子运动和正确遮挡同样重要。
- 局部动态灯光真实影响物体表面和邻近空间；前景、主体、后景不应同速同形变化。
- 禁止频繁或大面积高对比闪烁；正常模式控制白核亮度与覆盖，减弱动效关闭闪光、抖动和急速推拉。
- 可关闭音乐、音效及触觉；不要用提高响度或刺激频率替代声音设计。

### 6.3 数字与成果表达

- 不使用虚构倍率、金币堆、数字膨胀或无依据的大奖包装。
- 对小数精确收益，可用与实际变化对应的实体状态、资源名称和数字共同呈现；不可夸大收益或把未达阈值说成已达成里程碑。
- 精确资源值始终可查；正负分明，负成本不能被庆祝遮蔽。多个真实轴可在同一画面组合，不必机械地为每个轴重新播放整段爆炸。
- 实际数值增长必须确定性、单调、不超报；最终收据与业务账本一致。动画不触发额外发奖。

## 7. 事件类型与差异化表现

| 事件 | 核心意义与视觉动作 | 收束方式 |
| --- | --- | --- |
| 普通当日行动 | 简洁展示动作完成、实际成本、即时收益 | 快速确认；未来回声只显示日期和已安排内容 |
| TIME ECHO | 过去行动印记沿真实时间路径抵达、接触、兑现 | 实际成果与来源对应，保留明细 |
| CASCADE | 真实节点按拓扑顺序响应；分叉与合流可辨 | 显示真实因果结构和最终合计，不虚构节点 |
| 未来轨道·能力 | 知识结构、工具、透镜等主题实体形成 | 实际能力状态 |
| 未来轨道·关系 | 角色互动、两个端点真实连接 | 实际关系状态 |
| 未来轨道·财富 | 储备容器、真实资源汇聚 | 实际储备记录 |
| 长期目标达成 | 对真实里程碑给出专属动作与成果画面 | 明确已达条件及后续自主选择 |
| 预演/预测 | 清楚标记模拟与不确定性，展示信息 | 不当作已完成或真实获奖 |
| 失败/负面回声 | 清楚表达原因、代价与恢复方向，温和呈现 | 不制造近失或诱导立即再试 |

连续多个真实节点可在同一舞台自然连接，不要重复完整远景、特写、爆炸和结算。普通事件不套大奖演出，重大事件也不得无视玩家的跳过与弱动效选择。

## 8. 开发优先级与交付计划

P0-A：锁定实际最新非主分支与 commit，记录实测 APK 对应版本；读取 V2/V3 文档和现有实现。选取一条可复现、具有真实正向结果的 TIME ECHO 作为样片，记录原版完整录像、事件快照、cue时间和设置。

P0-B：实现情绪分镜、动作轨道、真实接触点与成果揭晓协同；复用V3美术及特效系统，修正阶段脱节。先做一个完整样片，不同时铺开所有事件。

P0-C：补足样片的原创/授权美术资产、火焰和光照，加入原创音画同步；正常、低档、减弱动效均应保留含义与可读性。

P0-D：同一 commit 实际 Unity 渲染、Android 构建与真机录像；与此前参考及旧版 HORIZON 对照。只有质量达标才扩大范围。

P1：推广到真实 CASCADE、三种未来轨道、重要里程碑；建立可复用 profile 而非相同模板。逐类检查真实结果与主题差异。

P2：覆盖其余事件，做性能调优、回归、资源许可检查与长期可维护性验收。

## 9. 验收门禁（禁止用代码存在代替体验达标）

### 9.1 主观体验评价

由用户或自愿测试者观看真实录像并按1–5分评价，记录具体时间戳与原因，不采集生理指标，不以停留时长、连续游玩次数、追逐冲动或多巴胺作为优化目标。

| 编号 | 评价项目 | 达标说明 |
| --- | --- | --- |
| E01 | 理解 | 能迅速说清正在呈现的真实事件 |
| E02 | 主体吸引力 | 主体具有美术吸引力及明确主题 |
| E03 | 铺垫质量 | 前段每一步都具有动作或叙事意义，不感到单纯等待 |
| E04 | 力量感 | 主体预备、发力、释放、反作用清晰 |
| E05 | 空间联动 | 光效、场景、镜头和主体彼此协调 |
| E06 | 高潮与反差 | 转折清楚，高潮有视觉与叙事意义 |
| E07 | 获得感 | 结果直观、真实、与之前行动有关 |
| E08 | 收束 | 演出自然结束，结果清晰可读 |
| E09 | 差异化 | 不同类型的演出无需只靠文字区分 |
| E10 | 自主性 | 可跳过、暂停、减弱动效且不损失结果 |

建议主样片 E01–E10 每项至少4分，并记录未通过的具体原因；这是拟议主观门槛，不是客观相似度百分比。测试者反馈不一致时保留差异，不强行宣布通过。不得宣称与途游捕鱼完全相同、保证爱上游戏或产生特定神经化学反应。

### 9.2 工程与视觉证据

- 每次记录 commit、设备、画质、分辨率、录屏帧率、实际事件ID与精确收益。
- 输出实际连续录像、主释放前后逐帧截图、cue日志；构造事件明确标 fixture，真实事件标 actual。
- 核对来源、动作接触、爆发与成果首次出现的时间；同时检查收据和数值真实正确。
- 9:16及长屏布局、正常/低档/减弱动效分别测试；确保不会因画质下降丢失结果。
- 验证暂停、跳过、回放、后台恢复和取消均不重复结算；原有玩法及存档回归必须通过。
- 同一提交 CI、Unity 编译、Shader 导入、Android APK、目标设备性能测试。沿用V3拟定60fps正常档、30fps低档目标，实测前标未验证。
- 比较同设备、相近观看尺度及相同事件阶段的真实录像；美术、动作、能量、空间与叙事各自评估。不把截图或HTML演示作为实际商业渲染证明。

## 10. 最终开发指令

后续每一轮 HORIZON 动画开发以 V2（能量）、V3（美术与空间）、V4（情绪与叙事）共同为基线。先核实最新分支，再制作一个真实、完整、可跳过的 TIME ECHO 样片；根据实际视频和体验反馈迭代。只有经验证后，才向其他事件推广。不要仅凭新增 Shader、提高亮度、增加粒子或编译成功就宣称视觉目标达成。

**最终目标：让真实行动的成果具有可感知的美感、力量与意义，让玩家在保持自主性的前提下享受完成与成长。**

本文件是设计与实施规范，不是已实现代码，不代表已经完成 Unity 渲染或真机验收。
