# v0.4.2 逐章工程验收

唯一基线：[Master Product Specification v0.4.2](MASTER_PRODUCT_SPEC_V0.4.2.md)。规则版本12、牌池版本10；旧局按原版本继续。

本轮按53章固定207个检查项验收，不以类名或按钮存在计完成。每章等权，章内检查项等权；明确的部分交付最高记0.5，未完成、未执行或失败均记0。检查项、相关测试名、已知限制在 [固定验收清单](../tools/acceptance_catalog.py)；[报告脚本](../tools/build_product_acceptance.py) 只合并同一提交的Unity和在线服务执行证据。

CI必须同时满足：所有观察到的测试通过、综合工程评分严格大于85%。`HORIZON-v042-Product-Acceptance`构建附件记录具体分数、源码树、清单哈希、逐项证据与未完成项。**没有同提交执行报告，不能宣布达到门槛。**

工程评分描述实现与已展示行为。它不是好玩程度、市场完成度、留存或现实迁移成功率。首次玩家理解、真实用时、盲听/触觉辨识、Android真机、本人Azure/DeepSeek资源、公网双人服务、支付和完整多日现实轨迹仍保留缺口。

当前主流程：三张有厚度的立体手牌 → 点击比较或实际拖入未来 → 当日结果 → 回声集中返回 → 玩家预测并对照 → 目标专属困难 → 恢复/求助后再行动 → 因果链与个人模式 → 未来站、地图 → 自愿现实小动作。新局支持12/30/60天，十种行为Boss；Mirror主动重现最近的个人节点，长期投资具有独立储备与复合兑现条件。

卡牌修复的是实际触摸命中：表面接收射线，按屏幕和Canvas坐标移动，有抬起/倾斜、目标命中、圈外返回与一次提交。Azure粘贴`/openai/v1/responses`会优先采用Responses协议，模型名称留空时读取同源模型列表；没有可读模型列表则要求实际部署名，不猜测部署。

在线双人服务包含两个成员的共同起点、邀请、公开时间线同步、分歧比较和经验投递；服务可自托管，尚未提供默认公网地址。分享保留GIF，并增加真正10秒H.264/AAC MP4。Editor录制和解码属于自动验收范围，Android原生编码与系统接收属于真机验收范围。

## 复现

1. 运行全部Unity EditMode测试（必须有GPU/Xvfb，不能使用`-nographics`）。
2. 两个Node服务测试输出JUnit；分享测试通过真实UI录制MP4，独立用ffprobe检查音轨、帧数、尺寸和时长。
3. 运行 `python3 tools/build_product_acceptance.py --results <Unity结果目录> --enforce`，失败项保持0分。
4. 所有检查通过后构建同提交Android APK，检查包名、版本、ABI、清单、签名及源码树一致性。

没有自动测试能够证明现实动作确实发生；Reality Node明确代表本人主动报告。也不能把不同PCM/震动波形当作玩家辨识效果的证据。
