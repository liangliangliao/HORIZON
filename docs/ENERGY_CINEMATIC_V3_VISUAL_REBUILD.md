## 2. 源码审计与根因假设

当前分支已存在 CinematicEnergy.ChargeAt、EnergyRelease、HorizonEnergyRelease.cginc 的解析流光/噪声火焰、HorizonImmersion.shader 与前/后景 camera-facing 光膜。不是继续新增一个火团公式就可解决。FrameImmersion 依赖 showcaseCenter/immersionFocus，主要以面向镜头的 quad 组织光层；InResultShot 切换到独立 resultLight，可能造成能量在镜头交接时重置；应以同一世界锚点与 cue 交接验证，而非直接断言是录屏具体 bug。EnergyRelease 主冲击时钟与 Outcome 的数值行起点相分离，后者 ChangeSeconds=2.8s；结果行可再采样局部 release，但不保证主高潮与真实成果首次可见同步。CinematicEnergy 有 verifiedRelease + Combo 档位过滤，某些非数值里程碑无完整释放属语义/路由差异，需用实际 event trace 验证。Jackpot 的 detailTremor 只在特定物品预览段有效；电影场景使用共享舞台/圆环，主题差别不能靠换文字。以上是代码可核实结构与推断；不能从录屏反推精确 shader 或证明录屏来自当前代码。

## 3. 重构原则：先完整样片，再推广

保留 V2 单导演时钟、真实资源快照、确定性、结算幂等、低画质/弱动效/跳过/暂停；不改业务规则、不编造倍率、收益、因果节点、待兑现日期或假随机中奖。普通操作轻量，重大成就才用完整演出。不强迫等待、不制造近失奖励。采用真实结果可立即查看的收据；语义字幕的阅读时间保留在结果卡或可展开收据内，不以固定阅读时长拖住每一段视觉高潮。现有阅读测试若需调整，明确先保留信息可读性并新增可回看/可跳过验收，不能简单删断言。

第一优先做「试着求助/整理作品」共用箱体的一条真实正向 TIME ECHO/有真实收益的事件样片；负向成本单独简短展示。以 Unity 竖屏实际渲染、同屏慢放对照为唯一视觉验收入口，先不铺开全部事件。之后再做三方向未来轨道与真实 CASCADE。

## 4. P0：导演时间、舞台、主体与能量同一事件

建议为现有 RewardDirector/RewardPlan 增加按事件/档位选择的演出 profile 与表现 cue 映射，避免第二套业务导演。所有轨道由现有 clock 可重播采样。核心数据：EventReceipt(immutable)、VisualProfile、WorldAnchor、ShotCue、ChargeCurve、MotionTrack、LightTrack、EffectCue、OutcomeRevealCue、SettleCue。每个节点须记录 cue 时间、世界位置、渲染档、结果值。实际结算与画面显示分离。

Major 样片建议起点（非参考实测精确参数；可调）：0–0.35s主体构图与微光；0.35–1.2s箱体局部挤压/倾斜、边缘点亮、短粒子；1.2–2.6s三波非线性蓄势、逐级增长的宽/细射线与冷暖过渡，镜头跟随；2.6–2.9s收紧/临界短停，主体仍可读；2.9s释放（局部柔边白核+同步动作、点光反射）；2.93–3.5s非规则火焰卷动及前/后景碎粒、箱盖真正打开；3.0–4.2s冲击前沿扩散、火星/短拖尾/落物；3.15–4.25s真实正向资源值开始增长，跟随奖励物入位，成本用另一明确轨道；4.25–5.5s终值、汇聚、余光；之后可查看完整收据。时间轴仅表现起点，按现有阅读要求与实际事件调节。主爆发到第一次真实结果/数字开始建议<=0.35s（不隐藏早已结算数据）；多个轴可组合入位/同时可读，避免每轴重置整个镜头；精确小数保留真实账本数值，初始不将 +0.0000 作为长期主视觉，数值单调且不超报。

舞台：以真实主题场景作为全屏背景，主体/动作/光效占用主视觉区，普通HUD及说明页暂退；保留小型控制和安全区。手机9:16、20:9构图独立适配；不让底部大面积空黑区占主画面，也不牺牲阅读。主体实际相对尺寸、镜头推进/拉远与 release 对齐；相机运动有限、可关闭。主体使用动作曲线/AnimationClip，而非仅增加震屏：预备姿势、重心改变、盖子/铰链、反作用、恢复。局部位置/旋转/挤压幅度按模型尺寸调试，不统一固定。人物、道具与光源锚点相连，特效跟随动作，发力点/缝隙/接触面明确。

## 5. P0：真实特效资产及空间合成

- 美术先行：制作/授权原创箱体、核心、人物与主题资产，倒角、轮廓、纹理、金属度/粗糙度、法线、AO、反射探针、接触阴影；角色动作不再只依赖程序几何体。真实资产许可清单。避免复制参考游戏标志/角色。
- 现有解析 Shader 保留作为辅助或低档；主爆发使用原创高质量 flipbook（如8×8共64帧，透明纹理或序列，具体分辨率依据目标机预算）、多张交叉/分层 billboard、噪声扭曲网格、火星 Ribbon/Trail，必要时以离线制作的火焰模拟序列表现卷曲、翻滚、分裂、消散；不是仅用二维圆形噪声扩大。
- 细射线、宽幅锥束、光点、星芒、环形/非规则冲击波、火团、残余灰粒分别有独立生命周期和速度。向内蓄积与向外释放不同方向；射线沿真实锚点发射，不连续地重复完整放射背景。前景、主体表面、主体后方和深景各自正确遮挡和透视；使用深度测试、软粒子及限量透明混合，不强制把所有效果放在背后。
- HDR/URP Bloom与局部实际灯光协同。动态光源照亮主体表面与邻近桌面/平台；色彩从冷到暖/主题峰值而非一律金色，曝光/反射/背景明暗随同一 cue。白色光核局部柔边、持续时间与覆盖面积受限；避免频繁、大面积高对比闪烁；减弱动效关闭闪光、抖动、快速运动，保留结果。
- 扩散波要有空间传播，冲击前沿、余辉、火团扩散与实体运动共享中心；避免中心不变的平面圆环充当全部爆炸。低档可用预烘焙 flipbook+一层柔光，并保持阶段、主体及真实终值。
- 粒子池与 GPU/CPU 合理分工，实际 Android 验证 URP/图形API；透明 overdraw、fill-rate、内存、发热/GC测量后定预算。不要为追求更亮直接叠加全屏透明层。
- 音画：原创预备、释放、余波、真实数值接触声/触觉，共同 cue；参考音轨尚未分析，不宣称复刻音色；静音和弱动效可用。

## 6. P1：差异化演出与结果呈现

- 时间回声：来源行动的实体印记沿时间轨迹抵达，落点与实际资源一致；使用独立世界锚点。每个实际结果可查看来源与原始数值。
- 未来轨道：能力为透镜/知识结构、关系为两条连结光轨/角色动作、财富为实际储备/钱包的主题装置；至少三套形状、动作、镜头、光色和最后落点，不可只换标题。点亮真实节点，已点亮不得重复宣称新成就；非数值里程碑使用状态变化而不是假计数。连续多个点亮合并为一个舞台内的逐节点演出与总览，避免三次相同远景开场和结算。
- CASCADE：实际父节点按拓扑点亮，分叉可辨、合流共享真实中心，传递光从上游抵达下游后才触发；各节点局部 burst、全局高潮只在真实合流/结算发生，文字随因果证据显示；可跳过，未知来路不虚构。
- 走进未来：门、角色、路径构成明确动作（走近→触碰/开启→场景变化），若事件仅为信息/预测则保持温和，不强行庆祝或显示资源增加。
- 每类 Profile 有独立动作、材质、视觉色谱、镜头构图与声音；低档压缩，高档增加真实阶段。普通行动不应套大型奖箱。

## 7. 验收门禁（每条记录 pass/fail/未验证和证据）

V3-01 样片完整：提交同一实际 event 的 Unity 正常/低档/弱动效录像，含时间戳、commit、设备/分辨率/画质/录制fps、真实快照；不能只给截图或HTML演示。参考片段同屏等宽、等主体尺度、等阶段比较，不宣称完全一致。
V3-02 蓄势：初始明确弱光，至少两次局部变化，主体位姿/灯光/射线均有变化；连续视频不能仅看光强图。
V3-03 爆发：白核、火团、前沿/余波在相邻实际帧可区分且有重叠，主体表面及空间受光，非规则火焰有独立轮廓演化；短闪安全，低动效无强闪。
V3-04 协同：真实正结果首次可见及计数与主释放/道具落点衔接；以 cue trace核对偏移，不能把成本包装成赢奖。0.35s为主样片目标，真实证据不符则调整。
V3-05 构图/材质：主体清晰且前中后景实际遮挡，不被黑色UI或静态光膜压住；数值、标题及结算均清楚可读，正负区分；在竖屏两种长宽比验收。
V3-06 变体：未来轨道能力/关系/财富三条录像不用文字即可区分；CASCADE分叉与合流有真实拓扑证据；连续播放不重复整段模板。
V3-07 业务一致：所有真实值、日期、节点、余额与旧规则一致；中断/跳过/回放不重复发放；弱动效和静音仍完整显示结果。
V3-08 性能：实机目标60fps，低档稳定30fps（拟定）；采集p95帧时间、GPU/CPU、内存、GC/发热；同一commit CI、Shader导入、APK构建。未运行标未验证。
V3-09 审美：同手机同观看尺寸，以源视频和实现录像盲化比较主体动作、光效动态、火团、空间、材质、数字、节奏、辨识度；每项1–5分并附具体失败片段。建议每项>=4且无核心失败后才推广（主观门槛，不是客观相似度百分比）。用户实际验收未通过则继续改，不用测试数代替审美。
V3-10 采证：录制连续帧并导出主爆发前后逐帧接触图、亮度/覆盖与主体位移轨迹、cue日志。全帧/主体ROI分别量化，通知遮罩排除，不把高亮像素当视觉质量唯一指标。

实施顺序：A 真实事件回放/记录、单样片导演与UI重构；B 专业资产+爆炸/场景光照/数字；C 真机对照审核后做 Orbit/CASCADE、扩展全部场景；D 回归、性能与素材版权核验。此次仅保存方案，不改运行时代码，不宣称已验收。
